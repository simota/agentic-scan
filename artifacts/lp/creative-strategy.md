# クリエイティブ戦略(ターミナル / エージェント版)

2026-11-19 に、ブランドとデザインを一から作り直した。前の版は、墨色・生成り・明朝体・細い罫線のエディトリアル調だった。これは AI が生成する LP によくある型で、オーナーからも「AI 生成感が強い」と指摘があった。オーナーが選んだ方向は「ターミナル / エージェント」。

## コンセプト

**製品が実際に動く場所で、製品の実物を見せる。**

agentic-scan は、エージェントのセッションの中で呼び出され、`findings.json` とダッシュボードを残すスキル群である。そこで LP の主役を、その出力そのものにした。具体的には、同梱サンプルにコマンドをかけた結果である。印象を作るために作文はしない。画面に出す端末の出力は、どれも実際に実行したコマンドの結果をそのまま載せている。

## 核になるメッセージ

- 見出し: 「コードに触れずに、裏の取れた指摘を。」
  - 「コードに触れずに」は read-only を指す。各スキルの README と SKILL.md で確認済み。
  - 「裏の取れた」は verdict を指す。security-scan の README に「every finding gets a verdict … with evidence」とある。
- 補足: 「どの指摘にもファイルと行と検証の判定がつく」。
- 署名(この製品にしかない一点): ヒーローの台帳の `F-004  High  FalsePositive` の行。
  - 誤検知と判定された指摘が、消されずに根拠つきで残っている。
  - これは security-scan の規則「Never: delete a finding judged false; mark it FalsePositive …」に基づく。bug / infra / logic / data-integrity / test-gap の各 SKILL.md にも同じ規則がある。
  - 他のレビューツールの宣伝文句ではなく、製品自身のデータが「確かめてから渡す」ことを示している。

## コピーの方針

- 機能名より、訪問者が得るものを書く(書き換えられない、判定つきで届く)。
- スキル名、コマンド、判定値は、英語のまま等幅で書く。訪問者が実際に打つ文字列と同じにするため。
- 前の版のうち、事実と合わなかった表現は直した。「12 のスキルが同じ手順」は誤りだったので、スキルごとに README の工程を載せた。
- 数字、導入実績、利用者の声は載せない。リポジトリに根拠がないため。

## コンバージョン目標と導線

- 主 CTA: 「導入手順を見る」(`#install`)。その先にあるのは、clone、`make link`、エージェントに頼む、の 3 ステップで、コピーボタンが動く。
- 副 CTA: 「出力サンプルへ」(`#output`)。実際のダッシュボード 4 種を見せる。
- 制約: リポジトリは非公開。この点は導入の節に明記し、GitHub へのリンクも置いた。

## セクションの構成

1. Hero: 見出し、リード、CTA。右側(モバイルでは下)に、`jq … | column -t` の実出力の台帳を置く。
2. skills: `make list` の実出力を目次にする(各行が節へのリンク)。12 のスキルそれぞれに、見る観点、README の工程、同梱サンプルの指摘 1 件を添える。
3. verify(反転した帯): read-only / verify / keep / decide の 4 つの決まり。
4. output: 実際のダッシュボード 4 種をタブで見せる。`make demo` の実出力と、出力形式の一覧も置く。
5. install: 3 ステップ、動作要件、非公開の明記。
6. FAQ と footer。

## デザインの意図

- 等幅の書体がブランドを担う。ワードマーク、ナビ、コマンド、判定、スキル名に使う。
- 日本語の本文は、読みやすさのためにゴシック体にする。
- 色は、スキルのダッシュボードが使う重大度の色(High / Medium / Low / Info)をそのまま意味のある色にした。地の色は紙ではなく、冷たいグレーにした。
- 避けたもの: 黒地に緑のネオン、光彩や走査線、偽のタイピング演出、macOS のウィンドウ枠、グラデーションの塊。
