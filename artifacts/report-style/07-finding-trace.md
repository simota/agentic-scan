# 07 指摘トレース

## コンセプト

指摘を記録順に並べ、横軸上の位置と行末の検証判定で一覧を追う。選んだ指摘の詳細は、該当ファイル、根拠、修正方針の順に読む。

## agentic-scan らしさ

トレースの各行はサンプルの指摘 ID、場所、重大度、検証判定から構成し、誤検知の F-004 もその位置に残す。LP と同じ等幅書体と重大度色を使う。軸は JSON 配列の順序であり、開始時刻・所要時間は未記録と明示する。

## 横展開

- **ux-scan** は画面や利用導線に沿って記録順の起点を決め、該当画面、観察根拠、改善案を順に追えるようにする。
- **bug-scan** は指摘詳細で履歴上の起点と現存箇所を対応づける。時刻付きの履歴を表示する場合は、コミット日時や記録時刻の意味を軸に明記する。

## 組み込みと工数

**中〜大・2〜3人日程度**（security-scan での初回組み込みと確認）。`render.py` の `DASHBOARD` が生成する一覧をトレース行に差し替え、元の順序を保持したまま既存フィルタ、詳細展開、アンカーを接続する。PDF 用の `render_assessment_html()` には本文から参照できる簡易トレースを追加する。`dashboard.css` では軸と判定列、狭幅の縦表示、印刷用の省スペース表示を定義する。既存データから順序を導けるため、データ形式の変更は不要。

## 弱点

横軸が示すのは順番だけなので、件数が多いと点が密集して比較しにくくなる。画面が狭い場合は横軸が縦の一覧に縮退し、追跡の手がかりは指摘の順番と判定になる。時刻付きの計測が必要な用途には、採取元の追加が必要になる。
