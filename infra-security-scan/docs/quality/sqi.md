# SQI — Software Quality Improvement Index (infra-security-scan)

Evaluation criteria, weights, and measurement conditions were finalized in this file **before improvement work began** and frozen in the same commit as the pre-improvement baseline. Post-improvement re-scoring uses the exact same criteria, with results appended to the "After Improvement" section at the end (the criteria body is never modified).

SQI is a custom rubric for this repository, not a physical quantity. Numbers are recorded with a distinction between "rubric score", "measured value", and "expert (AI) assessment". No real-user testing was conducted.

## 0. Evaluation Scope and Conditions (Fixed)

| Item | Fixed Value |
|---|---|
| Target code | `skills/infra-security-scan/scripts/*.py` (vendored `scan_report_kit/` is excluded from code evaluation under the contract that changes happen upstream, though it is included in rendered UI appearance) |
| UI | `dashboard.html` (interactive) and `assessment.html` (print; PDF is printed from this HTML) generated by `render.py` |
| Data | `examples/findings.sample.json` (en), `examples/findings.sample.ja.json` (ja), scale dataset `tools/make_big.py` (1,009 findings) |
| Viewports | 1280 / 1024 / 768 / 390 / 320 px, light and dark (`prefers-color-scheme`) |
| Browser | Bundled Chromium (Playwright), axe-core 4.10.2 |
| Representative tasks | T1 Find the most severe open item / T2 Open finding details and source excerpt / T3 Filter by perspective and provider / T4 Copy for LLM / T5 Read unchecked perspectives (coverage gaps) / T6 Open the print report |
| Change scenarios | S1 Add a baseline rule / S2 Change excerpt redaction policy / S3 Add a schema field / S4 Change dashboard display / S5 Change HCL parser |
| Weights | SQI = 0.25·DQI + 0.25·AQI + 0.25·VQI + 0.25·UXQI (all areas covered; weights unchanged) |
| Acceptance criteria | `make check` all pass, no new axe violations, median performance regression within measurement noise (±10%), existing CLI inputs/outputs and exit codes unchanged |

Measurement tools are in `docs/quality/tools/` (outside the skill; requires Node Playwright and axe-core).

Evidence levels: E0 unverified / E1 code or screen observation / E2 reproducible static analysis, automated tests, or systematic manual verification / E3 empirical measurement, fault injection, or multiple independent sources of evidence.

## 1. Scoring Anchors (0–5 per item, item-specific formulas)

### DQI

| Item | Weight | Criteria |
|---|---:|---|
| D1 Separation of concerns | 20 | Count X: total number of responsibilities across modules that are outside the module's primary responsibility and have a different reason to change. 5: X=0 / 4: X=1–2 / 3: X=3–4 / 2: X=5–6 / 1: 7+ |
| D2 Cohesion | 15 | Count P: cross-module imports of private names (starting with `_`), plus mixing of unrelated public functions. 5: P=0 and no mixing / 4: P≤2 or 1 mix / 3: P≤5 / 2: P>5 |
| D3 Interfaces & contracts | 15 | 5: All CLIs document usage and exit codes, data contracts have both executable validation and documentation, and library surfaces are explicit / 4: First two met / 3: Only one met / ≤2: Mostly implicit contracts |
| D4 Modifiability | 15 | Count N: number of change scenarios S1–S5 that force edits (or re-verification) in a module that does not own that concern. 5: 0 / 4: 1 / 3: 2 / 2: 3 / 1: 4+ |
| D5 Readability | 10 | 5: Consistent naming, rationale comments, and section structure, with no need to skip unrelated sections in a single file / 4: Consistent, but unrelated sections coexist in a large file / 3: Locally unclear |
| D6 Testability | 15 | 5: All regression tests run offline in under 1 minute, external dependencies (PDF engine, etc.) are replaceable, and boundary/mutation/differential tests exist / 4: First two met / 3: Partial |
| D7 Invariants & exception handling | 10 | Count K: swallowed exceptions (continuing after `except` without logging or re-raising, producing wrong results). 5: K=0 with input size and depth limits validated / 4: K=0 / 3: K=1–2 / 2: 3+ |

### AQI

| Item | Weight | Criteria |
|---|---:|---|
| A1 Module boundaries & dependency direction | 20 | Deductions from 5: circular dependency −2, module transitively imports unused components −1, cross-module private name import −1 |
| A2 Layering & data flow | 15 | 5: Single source of truth (`findings.json`), unidirectional stages (scan→merge→render→check), outputs bound to the record via digest / 4: Unidirectional without binding / 3: Reverse flow exists |
| A3 Change impact locality | 15 | Count U: number of CLIs that do not use a component yet are affected by changes to it (via import). 5: 0 / 4: 1 / 3: 2–3 / 2: 4+ |
| A4 Contract & data integrity | 15 | 5: Schema validation, referential integrity, atomic writes, and artifact staleness detection are all covered by automated tests / 4: 1 missing / 3: 2 missing |
| A5 Fault tolerance & isolation | 10 | Count F: tools that do not need `iac_scan` yet fail under fault injection (`tools/fault.sh`: makes `iac_scan` fail at import time). 5: 0 and external engine failures continue with warning / 4: 1 / 3: 2–3 / 2: 4+ |
| A6 Security & privacy boundary | 10 | 5: Read-only operation, secret redaction, output path checks, and symlink checks are tested / 4: 1 missing |
| A7 Observability & operability | 10 | 5: All failures listed on stderr with reasons, exit codes documented, progress check command available, and verbose diagnostic output selectable / 4: Last one missing / 3: Missing reasons |
| A8 Scalability | 5 | 5: Input size and work budgets enforced, and UI interaction stays under 50 ms on a 1,000-finding record (measured) / 4: Budgets enforced without scale measurement / 3: No limits |

### VQI

| Item | Weight | Criteria |
|---|---:|---|
| V1 Visual hierarchy | 20 | 5: Emphasis ordered as summary→attack paths→register, severity accent is the only strong color, primary actions are distinguishable, and no redundant emphasis / 4: 1 redundant emphasis / 3: 2+ |
| V2 Consistency | 20 | Count C: different representations for the same meaning found via systematic check (e.g., inconsistent use of color for similar status terms, raw enum values in one language only). 5: 0 / 4: 1–2 / 3: 3–4 / 2: 5+ |
| V3 Typography & readability | 15 | Count W: mid-word line breaks in English words (4+ characters) in the register and status labels (`ui_metrics.js`, total across en+ja × 5 widths). 5: 0 / 4: 1–4 / 3: 5–8 / 2: 9+ |
| V4 Layout & responsiveness | 15 | 5: Zero horizontal scroll across 5 widths × 2 languages, card layout at narrow widths, print layout provided / 4: Zero horizontal scroll but 1 layout break / 3: Horizontal scroll present |
| V5 Interaction states | 10 | Count S: missing required states (focus, hover, pressed/selected, empty state for 0 filter results, current toggle state). 5: 0 / 4: 1 / 3: 2 / 2: 3+ |
| V6 Color & contrast | 10 | 5: Zero axe `color-contrast` violations (both themes, both pages) and nothing conveyed by color alone / 4: Zero violations but 1 color-only indicator / 3: Violations present |
| V7 Whitespace & information density | 10 | 5: No duplicate display of the same numbers and consistent spacing / 4: 1 duplication / 3: 2+ |

### UXQI

| Item | Weight | Criteria |
|---|---:|---|
| X1 Task completion & efficiency | 25 | Execute T1–T6 with Playwright (AI-operated; not real-user testing). 5: All succeed with 0 dead ends / 4: All succeed with 1 dead end / 3: 1 failure or 2+ dead ends |
| X2 Discoverability & cognitive load | 15 | Count J: internal identifiers or non-idiomatic spellings in display labels (e.g. `FalsePositive`), plus presence of usage guidance. 5: J=0 with shortcuts and table of contents / 4: J=1–2 / 3: J≥3 |
| X3 Predictability & consistency | 15 | 5: Same action produces same result (re-clicking facet clears it, re-clicking same link re-displays it, etc.) verified by tests, no destructive actions / 4: Verified by observation only / 3: 1+ inconsistency |
| X4 Feedback | 10 | Count G: cases where action outcomes are communicated neither visually nor to assistive technology (count display, copy completion, 0 results, theme toggle state). 5: 0 / 4: 1 / 3: 2 / 2: 3+ |
| X5 Error prevention & recovery | 10 | Maximum number of actions R required to recover from a dead end. 5: R≤1 / 4: R=2–3 / 3: R≥4 |
| X6 Accessibility | 15 | axe violations (WCAG 2.0–2.2 A/AA + best-practice, both pages, both themes, expanded details) plus manual check gaps (keyboard, machine-readable state). 5: 0 violations and 0 gaps / 4: minor ≤2 or 1 gap / 3: serious 1+ or total 3+ |
| X7 Perceived performance | 10 | Median latency L from filter input to repaint on 1,009 findings, and CLS. 5: L<50 ms and CLS<0.1 / 4: L<100 ms / 3: L<200 ms |
